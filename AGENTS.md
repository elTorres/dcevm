# AGENTS.md

This file provides guidance to AI coding agents (Claude Code and others) when working with code in this repository.

## What this repo is

DCEVM: a patched OpenJDK HotSpot VM (Java 7/8) with enhanced class redefinition (add/remove fields, methods, supertypes at runtime). The VM changes are **not** stored as C++ sources. They live as a patch series in Mercurial Queues (mq) layout that the Gradle build applies to upstream HotSpot fetched with Git. The Java modules provide the test harness and an installer.

| Path | Role |
| --- | --- |
| `hotspot/.hg/patches/` | **The core of the project**: patch series in mq layout + `series` file (Mercurial is no longer used). Only these files are tracked by git, and everything else under `hotspot/` is generated by `./gradlew patch` (upstream sources plus a local Git history with one commit per patch). |
| `build.gradle` | Single root build script defining all subprojects (`hotspot`, `agent`, `dcevm`, `native`). Plus `Os`/`Arch` enums and the `InvokeMake` task. |
| `gradle.properties` | Build/test knobs: `hotspotTag`, `flavor` (`light`/`full`), `kind` (`fastdebug`/`product`), `jvmName`, `oops`, `targetJre`. |
| `dcevm/` | JUnit test suite for redefinition, plus `HotSwapTool` (redefinition driver used by tests). |
| `agent/` | Tiny `java.lang.instrument` agent that exposes `Instrumentation` to the tests. |
| `native/` | JNI library used by `SimpleNativeTest`. |
| `installer/` | Swing GUI that installs the built `libjvm`/`jvm.dll` into detected JDKs (`ConfigurationInfo` holds per-vendor/OS layout). |
| `hotswap/` | Historical original JKU patches (HS20). Not used by the build. |

## Key commands

```sh
./gradlew patch              # fetch HotSpot from github.com/openjdk/jdk8u (git) and apply the patch series for gradle.properties settings
./gradlew compileFastdebug   # or compileProduct; output in hotspot/build/<kind>
./gradlew installFastdebug -PtargetJre=$JAVA_HOME/jre   # install as alt JVM, run with -XXaltjvm=dcevm
./gradlew test               # full pipeline: builds+installs the VM, then runs tests on it
./gradlew :dcevm:test --tests com.github.dcevm.test.methods.AddMethodTest   # single test class
```

Things that trip you up:

- `test` has `ignoreFailures = true`. A green build does **not** mean tests passed. Read `dcevm/build/reports/tests/index.html` or `dcevm/build/test-results/`.
- `./gradlew patch` **wipes `hotspot/`** (except `.hg/` and `build/`) and starts again from the pristine tag. Any HotSpot edits not yet saved into a patch with `./gradlew :hotspot:refreshPatch` are lost.
- Legacy toolchain: Gradle 2.4 wrapper with pre-Gradle-5 syntax (`<<`, `compile`, `testCompile`). Run it on a JDK 7/8. Do not "modernize" the build unless asked.
